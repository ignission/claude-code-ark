aggregate root在庫（集約ルート）
  • 販売単位id
  • 引当可能数
  • 引当済数
invariant在庫 不変条件
  • 超過引当なし（NFR-03・並行性境界）
  • 引当は注文確定時（REQ-O-08/D11）
  • 取消で全量復元・同一Tx（未解決5: 仮置き）
design principle集約設計の原則（DDD）
  • 集約境界＝一貫性境界＝1コミット1集約
  • 集約をまたぐ参照は id のみ（オブジェクト参照しない）
  • 例外: 注文確定は単一Tx（検証→在庫減算→Order生成→セッション消費・P0-1）
  • 通知・read model 投影は outbox で結果整合
  • 決済は Payment BC へ分離・初版は台帳記録のみ（D9）
aggregate rootCheckoutSession（集約ルート）
  • 明細と数量の写し（作成時に固定）
  • 配送先は1つ（PMRD-77 B案/D3）
  • 希望納品日・備考（任意・D4）
  • 有効期限（サーバー発行）
invariantCheckoutSession 不変条件
  • 未消費かつ期限内のみ確定可（確定Tx内で判定）
  • 確定成功で消費（1セッション1回）
  • 消費済みへの再confirmは注文番号一覧を冪等返却
  • 二重生成防止 UNIQUE(session, supplier)
aggregate rootReturnRequest（集約ルート）
  • 事由: 不良品/誤配送/配送前期限切れ（PMRD-3）
  • 申請は到着後3営業日以内（暦・時計はPort注入）
  • 対象は明細の全数量のみ（部分返品なし）
  • 承認時に返金可能額を写し取る
invariantReturnRequest 不変条件
  • バイヤー都合の返品は不可（PMRD-3）
  • 同一明細への重複申請は部分ユニーク制約で防ぐ
  • 返金は商品代のみ・送料はサプライヤー負担
aggregate root（台帳）PaymentObligation（請求・返金台帳）
  • 種類: 初期請求 / 差額の追加請求 / 返金
  • 金額（MoneySen・銭整数）
  • 一意キーで二重記録を防ぐ
  • 初版は記録のみ・決済実行なし（D9）
