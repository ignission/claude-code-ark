# コンテキスト機構を足す前に

Ark は同種の機構を 4 回作って 4 回撤去した（Frontline / Beacon / flow / ark/context、
計 37,000 行超）。5 代目を作る前に、ここを通ること。

由来は #367 の対照実験 6 回と、その撤去（#401）。

## 1. ホストが既に提供していないか測る

**測ってから作る。** 4 代目は、ホストが既に持っていた機構を無効化して作り直していた。

| Manus の主張 | Claude Code が提供するもの | 4 代目がしたこと |
|---|---|---|
| 失敗をコンテキストに残す | 失敗した tool_result は原文のまま残る | `errors/raw.log` へ**書き出して context から除いた** |
| 復唱で注意を操作する | `TodoWrite` は**エージェント自身が書く** | hook が `additionalContext` で**注入した** |
| ファイルシステムを外部記憶に | native auto memory | 環境変数で**無効化して自作に置き換えた** |

検証のしかた（実測例）:

```bash
# 失敗が context に残るか: 自分の transcript で is_error の tool_result を数える
# → 実測 69 件、原文のまま残っていた
```

## 2. 成果物ではなく機構を写す

移植元の主張は「何を作るか」ではなく **「トークン列に何を起こすか」** で定義されている。

同じ名前のファイルが同じ場所にできることは、移植できた証拠にならない。
4 代目の 2 つの反転は、**成果物の水準では完全に一致していた**。

書く前に 1 行で答える: **この機構は、モデルが次のトークンを選ぶときの入力を、どう変えるか。**

答えが「ファイルができる」なら、それは機構ではない。

## 3. ループの所有者か借り手かを仕分ける

Ark は Claude Code のループを**借りている**。使えるレバーは境界に置くテキストだけ。

推論基盤に触る主張（KV-cache 前提のプレフィックス設計、ツールのロジットマスキング）は
**実装できない**。「後回し」ではなく **対象外** として最初に落とす。

土台の主張を落としたまま、その上に建つ主張だけを実装すると、
見た目は揃うが効かない。4 代目がこれだった。

## 4. 積荷と配達装置を別々に見積もる

4 代目の比は **10,350 : 71**（配達装置 : 積荷）。届く本文は 2 行だった。

配達が積荷より桁違いに高いと、**悪いアイデアを安く捨てられなくなる**。
捨てられないものは、効いているかどうかに関係なく残る。

**制約: 新しい機構は、既にある SessionStart hook
（`knowledge-session-start-hook.ts`）に載る形でしか作らない。**
専用の lifecycle（セッション識別・ロック・所有者・終了処理）が要るなら、作らない。

4 代目の不具合 10 件のうち **9 件は配達装置の中**にあった。

## 5. 自分のループの形を先に書く

どの主張が効くかは、ループの形で決まる。実装前に数字で書くこと。

- **人間が何分おきに介入するか**
- **1 タスクあたり何回ツールを呼ぶか**

Ark の通常セッションは人間が数分おきに割り込む。
**人間が復唱そのもの**なので、目標を言い直す機構を足しても何も足されない
（実測: 復唱あり / なしを実 Issue で 4 回、1 勝 1 分 2 敗）。

ただし **リモート / モバイル利用は人間が長時間戻らない**。
このループでは結論が変わりうるが、**まだ測っていない**。

## 6. 判断が要る場所は自動化されない

「この失敗から何が一般化するか」は変換ではなく判断。

4 代目は候補の収集を実装し（42 セッション中 33 で機能した）、
**候補から知識への昇格を実装しなかった**。263 行はすべて手書きだった。

手抜きではない。**失敗を context から追い出した瞬間に、
移植元には存在しない「何を昇格させるか」という判断が発生した**からだ。

作るなら、判断の自動化ではなく **判断を安くする方向**にする。

## 7. ホストの機能を無効化するなら、戻し方も書く

4 代目は `TodoWrite` / `TaskCreate` / `TaskUpdate` を repo の設定へ拒否として書き込み、
終了処理で戻す設計だった。機構ごと撤去したら**戻す処理が走らず、拒否だけが残った**。

- 無効化する理由を書く。書けないなら無効化しない
- 撤去したときに戻ることを、**撤去の PR の中で**確認する
