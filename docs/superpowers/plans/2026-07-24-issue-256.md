# Issue #256: 図ディレクトリを `.claude/diagrams` へ移す実装プラン

> **実装担当者向け:** この文書は設計承認用の実装プランである。実装は各 Task を Red → Green → Refactor の順に進め、1 Task を原則 2〜5 分で完了できる大きさに保つ。

**Goal:** 図の正準ルートを `docs/diagrams` から `.claude/diagrams` へ一括切替し、既存の文字列上の封じ込め、realpath / TOCTOU 検証、再帰一覧、MCP、作図 skill、表示ラベル、DB 復元、Ark 自身の図 fixture を同じ境界へ揃える。

**Issue:** GitHub Issue #256

**前提:** 設定機構や旧ルートとの二重読みは作らない。`DIAGRAM_DIR` は shared の単一 runtime 定数とし、server と client はそれを import する。静的 Markdown である diagram-authoring skill はパス文字列を重複保持せず、`DIAGRAM_DIR` から生成される `board_open.path` の説明を正準の書き出し先として参照する。

## 2. 設計判断

### 2.1 旧 `docs/diagrams` は読み取り互換を残さず一括切替する

**採用:** `.claude/diagrams` だけを正準ルートにし、server は旧物理ルートを列挙・読取・監視・更新しない。

**理由:**

1. #247 の一覧 identity を1つの `relPath` 名前空間に保てる。
2. #255 の削除で「同名図が新旧どちらにあるか」「どちらを削除するか」「tracked 状態をどう見せるか」という分岐を増やさない。
3. `DIAGRAM_DIR` がセキュリティ境界である以上、互換ルートの追加は単なる検索先追加ではなく、realpath 検証・TOCTOU 対策・監視・書戻しの境界を二重化する変更になる。
4. 旧ルートを read-only にしても、一覧から開いた図は既存の `diagram:submit` で書き戻されるため、本当に read-only にするには編集機能まで分岐が必要になる。
5. Ark 自身の tracked 5件は同じ変更で `git mv` でき、untracked 12件も明示的なローカル移行で保全できる。

旧ルートだけにファイルがある場合、一覧は空または新ルート内の図だけを返し、`board_open("docs/diagrams/x.diagram.html")` は旧物理ファイルを開かない。ファイル名省略形を補う現行仕様は維持するため、この入力が新ルート配下の `docs/diagrams/x.diagram.html` というネスト名として解釈され得る点は security bypass ではない。回帰 test は「旧物理ルートだけに置いたファイルを読まない」ことを固定する。

### 2.2 `lastDiagramPath` の旧値は prefix 移行せず `NULL` にする

**採用:** server 起動時の既存 DB data migration で `docs/diagrams/` prefix の `last_diagram_path` を `NULL` にする。schema は変えない。

**理由:**

- Ark は任意の managed repository にある旧ファイルが実際に新ルートへ移されたか保証できない。
- prefix だけを機械変換すると、未移行・削除済み・壊れたモデル・外向き symlink の保存値から stale tab を復元する。
- `lastDiagramPath` は図本体ではなく「最後に選んだ1件」のキャッシュであり、失っても図一覧または次の `board_open` で再構築できる。
- database layer に filesystem / realpath 検証を持ち込まず、既存 trust boundary の責務を崩さない。

**起動時 / 復元時の具体的挙動:**

1. `SessionDatabase.initialize()` が schema migration 後、旧 prefix の値だけを idempotent に `NULL` へ更新する。
2. その後 `SessionOrchestrator` が既存 tmux session と ttyd を通常どおり復元する。セッション、会話、profile、board token は削除しない。
3. `session:list` / `session:restored` の `lastDiagramPath` は `null` になり、Dashboard は diagram tab を自動復元しない。右ペインの開閉 localStorage は変えない。
4. `.claude/diagrams` の一覧は通常どおり取得でき、ユーザー選択または次の成功した `board_open` が新 prefix を DB に保存する。
5. すでに `.claude/diagrams/...` を持つ DB 値は変更しない。

### 2.3 `.claude/` が gitignore される repository ではローカル成果物として扱う

**採用:** Ark は `.gitignore` を変更せず、git tracking を図機能の前提にしない。

- `.claude/` 全体が ignore されても filesystem 上の作成、一覧、読取、更新、`board_open` は動作する。
- その場合、図が通常の `git status`、commit、clone で共有されないことを仕様上許容する。Ark の図は既定では worktree ローカル成果物という整理にする。
- 共有したい repository の owner は、その repository の方針として `.claude/diagrams/**` を unignore / track する。Ark が ignore 規約を自動編集したり `git add -f` したりしない。
- Ark 自身は `.claude/` 全体を ignore していないため、tracked 5件は移動後も tracked fixture として共有する。ローカル12件は従来どおり untracked のまま移す。

### 2.4 サブディレクトリの再帰を維持する

**採用:** `.claude/diagrams/**/*.diagram.html` を再帰列挙する。

#247 の既存契約、`resolveDiagramPath()` の nested path、`board_open`、現在図 identity を一致させる。直下限定へ狭める理由はなく、directory symlink を辿らず各 file を `readDiagramModel()` で検証する現行の強さも維持する。

### 2.5 ディレクトリは server 起動時に作らず、作図時だけ作る

**採用:** 一覧・読取・server 起動は directory を作成しない。diagram-authoring の書込手順と新規セッション prompt が、最初の図を書き出す直前に必要な parent directory を作成する。

- directory 無しの `diagram:list` は現行どおり `[]`。
- directory 無し / file 無しの `board_open` と `/api/diagram` は 404。
- read-only 操作や単に Ark を起動しただけで target repository を dirty にしない。
- `board_open` は「書いた後に開く」責務のままとし、空 directory や空 file を代理作成しない。

### 2.6 `DIAGRAM_DIR` の単一ソース

`packages/shared/src/types.ts` に `export const DIAGRAM_DIR = ".claude/diagrams"` を置く。既存の package root export を使うため package export map は増やさない。

- server の path resolver、reader、list、MCP tool metadata、session prompt が同じ値を import / re-exportする。
- web の option label は同じ値から `${DIAGRAM_DIR}/` を作る。
- E2E の fixture URL も同じ値を import して組み立てる。
- static Markdown の skill は directory literal を正準値として持たず、「`board_open.path` の説明に示された directory」を参照する。MCP の path 説明は `DIAGRAM_DIR` から生成するため、書き出し先の決定点は1つになる。
- `CLAUDE.md` と図 fixture 内の可視テキストは説明資料であり runtime source ではない。現在値へ更新するが、挙動はそこから決めない。

5. Ark serverを起動する。初回起動で旧 `lastDiagramPath` だけがnullになる。
6. 図一覧17件、新規 `board_open`、reload後の新 path復元を確認する。

## 7. ロールバック手順

1. Ark serverを停止する。
2. Issue #256 の実装 commitを `git revert` し、shared constant、server/client/MCP/skill/docs/E2Eを旧 rootへ戻す。historyを書き換える resetは使わない。
3. tracked 5図は revert により `docs/diagrams` へ戻る。
4. untracked 12図は移行時 manifest の明示 filenameだけを `.claude/diagrams` から `docs/diagrams` へ戻し、checksumと17件を照合する。recursive deleteや `git clean`は使わない。
5. `lastDiagramPath` の旧値も復旧する必要がある場合は、ロールアウト前の SQLite backupを server停止中に復元する。backupが無い場合でも session本体は失われず、「最後に開いた図」の選択だけが失われるため、旧版起動後に `board_open` し直せば再保存される。
6. 旧版の targeted diagram testsと一覧/openを確認してからserverを再開する。

新 prefix の DB 値を一括で旧 prefixへ置換する rollback SQL は使わない。rollout後に新規作成された図まで誤って旧 rootへ向けるためである。
