# issue-300: 文書型ページのコメント層（Phase 1） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `type: "doc"` の文書ブロックへ、CSP と既存モデル契約を保ったまま単発コメントを作成・表示・resolve できる Phase 1 のコメント層を追加する。

**Issue:** 300 (GitHub Issue 紐付けあり)

**Architecture:** `model.type === "doc"` の配信だけ既存編集ハーネスを注入せず、`data-ark-id` を走査する専用コメント層を注入する（graph 型の注入文字列は変更しない）。iframe は外部通信せず、既存 `ark:diagram-init` の MessageChannel port で親の `DiagramPane` に load/create/resolve を要求し、親が 10 秒 ACK 付き Socket.IO イベントを sidecar store へ中継する。sidecar は同階層の `<name>.comments.json` とし、図と同水準のパス封じ込め・open/fstat/realpath/stat・`O_NOFOLLOW` を適用する。doc の node↔`data-ark-id` lint は直接 Write 後の `board_open` と Socket.IO 保存の両境界へ置き、既存の全 ID 一意性検査は重複実装しない。

**Tech Stack:** React 19 / TailwindCSS 4 / Express / Socket.IO / better-sqlite3 / tmux / ttyd（monorepo: packages/{server,web,shared,desktop}）

## 前提の確認（実装を読んで確定した事実）

1. **設計7-4（node / field / edge / group の単一 ID 名前空間）は既に保存と `board_open` の双方で満たされているため、新しい lint は不要。** `parseDiagramModel` は単一 `seen` を作り（`packages/server/src/lib/diagram-model.ts:84-89`）、node（同:100-101）、field（同:115-116）、edge（同:145-146）、group（同:172-173）を同じ集合へ通す。Socket.IO 保存は `saveDiagramEdit` が受信 model を `parseDiagramModel` へ通す（`packages/server/src/lib/diagram-save.ts:35-40`）。MCP の `handleBoardOpen` は `openDiagram` へ委譲し（`packages/server/src/lib/board-mcp-server.ts:73-80`）、その実体は `readDiagram` 成功前に emit しない（`packages/server/src/index.ts:772-781`）。`readDiagram`→`extractModel`（`packages/server/src/lib/diagram-reader.ts:110-123`）→`parseDiagramModel`（`packages/server/src/lib/diagram-file.ts:69-75`）を通るため、Issue の「保存成功→`board_open` で重複拒否」はサーバー保存を迂回した Write で説明でき、`board-mcp-server.ts` や `diagram-save.ts` に同じ ID 検査を足さない。

2. **設計7-1〜3の node↔DOM アンカー lint は `model.type === "doc"` のみに適用し、配信境界と保存境界の両方へ置く。** graph/内蔵投影は `data-model-id` を契約としており（`packages/server/src/lib/diagram-builtin.ts:171-197`）、既存 authoring skill も同属性を要求する（`.claude/skills/diagram-authoring/SKILL.md:90-100`）。全図種へ `data-ark-id` を要求すると既存図を壊す。doc については「全 node id がちょうど1回」「全 `data-ark-id` が node に存在」「HTML 内重複なし」を共通関数で検査し、`readDiagram`（直接 Write 後の HTTP 配信・`board_open`）と `saveDiagramEdit` の差し替え後 HTML（Socket.IO 保存）の両方で失敗させる。`readDiagramModel` は一覧と保存 baseline の汎用読取口なので lint せず、違反した doc を `listDiagrams` から消さない。保存時とコメント mutation 時は `validateDiagramDocAnchors` を明示的に呼び、`readDiagramModel` の副作用には依存しない。

3. **コメント mutation は既存 MessageChannel + Socket.IO ACK パターンへ揃える。** 親は iframe load ごとに MessageChannel を作り `ark:diagram-init` と port を渡す（`packages/web/src/components/DiagramPane.tsx:498-560`）。ハーネスは受け取った port だけを capability として扱う（`packages/server/src/lib/diagram-harness.ts:3446-3467`）。既存 autosave は `socket.timeout(10_000)` の ACK を port へ `ark:diagram-autosave-result` として返す（`packages/web/src/components/DiagramPane.tsx:169-180,466-493`）。Phase 1 も iframe→port の `ark:diagram-comments-load` / `ark:diagram-comment-create` / `ark:diagram-comment-resolve` を、親→Socket.IO の `diagram:comments:get` / `diagram:comment:create` / `diagram:comment:resolve` へ変換し、`requestId` 付き結果を同じ port へ返す。server は client の `worktreePath` を信用せず `sessionId` から managed worktree を解決する。

4. **sidecar は図パスからのみ導出し、図と同水準の実体検証を行う。** `resolveDiagramPath` は `.claude/diagrams` 配下への文字列上の封じ込めを行う（`packages/server/src/lib/diagram-path.ts:68-85`）。読み取りは現行 `readRawVerified` の open→fstat→realpath+stat、inode/device 一致、実体の `DIAGRAM_DIR` 封じ込め（`packages/server/src/lib/diagram-reader.ts:38-78`）を踏襲する。書き込みは既存保存の `O_NOFOLLOW`（`packages/server/src/lib/diagram-save.ts:51-70`）に加え、同一ディレクトリ内の一時通常ファイルを `O_CREAT|O_EXCL|O_NOFOLLOW` で書いて atomic rename する。`order-flow.diagram.html` の sidecar は同じ directory の `order-flow.comments.json`、JSON の `target` は `order-flow.diagram.html` とする。

5. **sidecar 未存在だけを正常な空状態とし、壊れた sidecar を空へフォールバックしない。** 現行 reader も ENOENT だけを 404 に分離し、EACCES/EPERM/その他を別エラーにする（`packages/server/src/lib/diagram-reader.ts:79-99`）。同様に sidecar ENOENT はファイルをまだ作らず `{version:1,target,threads:[]}` を返すが、JSON parse、schema、target 不一致、サイズ超過、権限、symlink/実体検証の失敗は typed ACK error とし、`DiagramPane` とコメント層の双方に表示する。Phase 1 の status は `open | resolved` のみで、`orphaned` を黙って隠さず schema error とする。

6. **`diagram-list.ts` は sidecar を一覧候補にせず、`diagram-delete.ts` は Phase 1 で sidecar も削除する。** 一覧は `.diagram.html` suffix だけを候補にし（`packages/server/src/lib/diagram-list.ts:32-55`）、表示名/tracked も図本体から作る（同:61-73）ため production ロジックは変更不要で、sidecar が混入しない回帰テストだけ足す。現在の delete は図本体1ファイルだけを安全に unlink する（`packages/server/src/lib/diagram-delete.ts:114-196,271-289`）。コメントだけ残すと以後一覧から到達できない orphan file になるため、sidecar があれば同じ安全検証後にカスケード削除し、失敗は握り潰さず response error/warning に載せる。削除確認文にも「隣接コメントも削除」を明示する。

### 固定する既存契約

- 編集ハーネスの esbuild artifact 実測は **128,921 bytes / guard 131,072 bytes（残 2,151 bytes）**。graph 側へコメントコードを1バイトも混ぜず、doc 専用注入へ分離する。
- `DIAGRAM_CSP` は `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:`（`packages/server/src/lib/diagram-file.ts:25-27`）。コメント注入文字列にも `fetch(` / `import(` / `https://` / `innerHTML` / `insertAdjacentHTML` / 外部 stylesheet/font を含めない。既存 guard は `packages/server/src/lib/diagram-harness.test.ts:168-191`。
- `DiagramModel` / `DiagramNode` interface（`packages/server/src/lib/diagram-model.ts:15-54`）は変更しない。doc の block type は既存 `kind` と `ext` で表す。
- `packages/server/src/lib/diagram-diff.ts` / `describeModelDiff`（同:276-282）は変更しない。コメントの会話還流は Phase 2。
- `doc` は本文 HTML が正で、Ark が投影を生成する図種ではない。`BUILTIN_DIAGRAM_TYPES`（`packages/server/src/lib/diagram-builtin.ts:145-151`）へ追加せず、「自前 graph には触らない」分岐（同:217-239）も変更しない。
- MobileSessionView 等のモバイルコード、`packages/server/src/lib/database.ts`、DB schema は変更しない。DB が必要だと判明した時点で実装を停止して報告する。
