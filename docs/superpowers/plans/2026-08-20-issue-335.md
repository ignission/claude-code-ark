# issue-335: エラー捕捉と失敗継承 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 実行開始後の Claude Code tool failure の原文を欠落させない追記専用 JSONL として安全に保存し、既定では無課金の決定的な機械 summary、明示 opt-in 時だけの成功 fallback 付き LLM summary、および再起動 session への最大2000 bytesの失敗継承を実装する。

**Issue:** 335 (GitHub Issue 紐付けあり)

**Architecture:** agent 非依存の `hooks/capture-error.sh` は正規化済み failure event の検証と append-only 記録だけを担い、Claude Code 固有の `PostToolUseFailure` JSON 解釈は `adapters/claude-code/post-tool-use-failure.sh` に閉じ込める。機械 summary は時刻・locale 非依存かつ `## ` 見出しを生成しない固定形式にし、既存 `task-template.sh` の一行化と合わせて recitation の `## Plan` 境界を壊さない。LLM は `[loop.summarize] llm = true` と model/API key が揃う場合だけ機械 summary を入力に追加要約し、timeout・API失敗・schema不一致・行参照欠落では機械 summary を byte 単位で保持して exit 0 に fallback する。

**Tech Stack:** bash hooks / bash test / JSONL / TOML config
