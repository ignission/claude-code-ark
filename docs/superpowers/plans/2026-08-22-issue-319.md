# issue-319: doc 型ボードの本文 authorship Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `type: "doc"` の本文ブロックに「誰が書いたか」を持たせ、人間が下した決定と（別セッションを含む）エージェントの出力を、lint・ボード表示・エージェントへの規約の 3 点で区別できるようにする。

**Issue:** 319 (GitHub Issue 紐付けあり)

**Architecture:** 本文 HTML が正準 source である前提を崩さず、doc の各ブロック（`data-ark-id` を持つ要素）へ任意属性 `data-ark-author="human" | "claude"` を置く。モデル（`DiagramModel`）には何も足さない（二重管理を避ける。設計上「doc 専用 field を追加しない」制約も維持）。サーバーは配信（`readDiagram`）と保存（`saveDiagramEdit`）の両境界で語彙を lint し、doc モードのコメント層が属性を読んでバッジを描く。Claude への規約は SessionStart hook の context と `diagram-authoring` skill に載せ、`_examples` の文書サンプルを規約どおりに更新する。

**Tech Stack:** React 19 / TailwindCSS 4 / Express / Socket.IO / better-sqlite3 / tmux / ttyd（monorepo: packages/{server,web,shared,desktop}）

## 設計判断（Issue の論点への回答）

1. **authorship はどこに置くか → 本文 HTML の属性。** doc は「本文は HTML が正、model の label は抜粋」（skill）なので、model へ置くと二重管理になる。`data-ark-id` と同じ要素へ `data-ark-author` を並べれば、コメント層が既に走査している要素に情報が乗り、lint も `scanDiagramHtmlStartTags` の同じ走査で済む。

2. **語彙は `human` / `claude` の 2 値に固定する。** コメント sidecar は `author` 無し = 人間、`author: "claude"` = Claude の非対称で「誰が書いたか」を表している（#313）。本文も同じ語で揃える。ただし本文の既定の書き手はエージェント（Claude が Write/Edit で書く）なので、**無印は「人間の決定ではない」**と読む。読み手の規則は「`data-ark-author="human"` が付いたブロックだけを人間の決定として扱う」の 1 つにし、無印の意味論に依存させない。

3. **無印を lint で落とさない。** 既存の doc はすべて無印なので、必須化すると `board_open` が 422 で全滅する。落とすのは語彙外の値・`data-ark-id` の無い要素への付与・1 要素内の重複だけ。

4. **`human` をサーバーで検証可能にはできない。** ファイルは worktree の外から自由に書き換えられ、サーバーは `diagram:updated` で変化を知るだけで書き手を知る手段が無い。したがって `human` は「人間がコメント・会話で下した決定を転記した」というエージェントの宣言であり、その宣言を守らせるのは規約（SessionStart context と skill）の責務にする。誤った宣言を機械的に防ぐことは本 Issue の範囲外とする。

5. **差分可視化（論点 2）と同時編集の競合（論点 3）は対象外。** ボードの責務は「各ブロックを誰が書いたか」の表示までとし、「前回開いたときから何が変わったか」は tracked なら git、untracked なら `diagram:updated` による再読込に委ねる。last-write-wins も変更しない。いずれも独立した Issue として扱う。

### 固定する既存契約

- `DiagramModel` / `DiagramNode`（`packages/server/src/lib/diagram-model.ts`）は変更しない。
- `validateDiagramDocAnchors` の契約（node ↔ `data-ark-id` の 1 対 1）は変更しない。authorship lint は別関数にし、read/save の両方で anchors の直後に呼ぶ。
- コメント層注入物は 128 KiB 未満・CSP 禁止 token 無し（`diagram-comment-layer.test.ts`）。graph モードの動作は変えない。
- `DiagramPane` / Socket.IO イベント / DB schema は変更しない。
